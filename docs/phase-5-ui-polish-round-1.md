# Phase 5 — UI polish, round 1

## Scope

Frontend presentation only. The dark Manrope/mint identity, page structure and financial workflows remain. No backend, schema, money calculations, API, idempotency, ETag, recovery or activation behavior changed. Changes are uncommitted.

## Dialog root cause and fix

Tailwind Preflight resets element margins to zero. The shared native `.transaction-dialog` never restored the browser's automatic dialog margins, so `showModal()` put it at the viewport origin. A separate narrow-screen rule intentionally used `margin: auto 0 0`, making the mobile dialog a bottom sheet.

The shared style now explicitly uses fixed positioning, `inset: 0` and `margin: auto` at all widths, bounded by dynamic viewport height and horizontal gutters, with internal vertical scrolling and overscroll containment. The shared React Dialog renders into `document.body` through a portal. Native `showModal()` supplies the browser top layer, inert background, focus containment and modal semantics; the existing body scroll lock, initial input focus and return-focus handling remain. Every normal financial overlay uses this primitive, including transaction, budget, recurring, group, shared expense, settlement and cycle transitions. Mobile navigation remains an intentional side drawer.

Escape and backdrop clicks still call the caller's close guard. Pending operations remain non-dismissible, dirty drafts still require their existing discard decision, and uncertain requests retain the existing reconciliation/review behavior. No mutation waits for an animation.

## Readability and motion

Functional text now follows a 14px interface / 12px secondary scale, retaining larger headings and totals. Shared input values and modal selects/textareas use 16px; auth labels, hints and validation messages use 14px. Decorative auth artwork is unchanged. The normal entry now imports the existing cycle stylesheet: it was previously loaded only by the staged entry, leaving history cards unstyled and omitting the intended narrow tab layout. Group/member text, ledger rows, filters, budgets, recurring schedules and account details share the scale. Long account email is visible at 14px in the header and sidebar, safely ellipsized with a title; the keyboard-accessible account link opens the complete wrapping address. Important text keeps the established high-contrast palette.

CSS tokens specify 150ms feedback and 200ms modal entry with a restrained easing curve. Buttons have press feedback, links/navigation/fields transition colors and borders, and dialogs/backdrops/notices fade in with only a 6px entry movement. Existing page transitions remain. Closing is immediate, so completion, recovery and focus restoration never wait for animation. Reduced-motion preference disables CSS animation/transitions entirely, while existing React page transitions already respect the same preference. Status text, validation and focus rings remain visible without motion. No dependencies added.

## Verification and evidence

Final gate results are recorded below. Chromium uses the normal `server.js` plus Vite composition with a generated disposable `tallynest_fresh_v2_test_*` namespace; staged and integration tests run sequentially. Existing databases are never setup or cleaned by this task.

Browser regressions measure both dialog center coordinates against the actual CSS viewport, within 2px, and assert bounds and body scroll locking. Coverage includes group creation, lifecycle confirmation, shared expense, budget, recurring and personal transaction dialogs; the transaction form spans 1440, 1024, 768, 390 and 320px, including a 320×480 short viewport. Keyboard checks cover initial input focus, Tab/Shift+Tab containment, safe Escape and trigger focus restoration. Reduced motion is asserted. A 720×450 CSS viewport tests the reflow available at 200% zoom on a 1440×900 display; this is a layout-equivalent check, not a claim of native browser zoom control.

Sixteen authentic screenshots are generated by the normal browser test in `output/playwright/ui-polish/` (ignored local artifacts): login, register, group-dialog, shared-expense-dialog, cycle-workspace, transaction-dialog, mobile-dialog, narrow personal/account/group pages and narrow budget/recurring forms. They contain only disposable test identities.

## Remaining limits

Native permission/unload/browser confirmation prompts are controlled by Chromium, not application CSS. The mobile navigation is deliberately a drawer rather than a centered financial form. No hosted, Safari, Firefox or assistive-technology validation is claimed. Closing animation is intentionally omitted to preserve immediate unmount and focus restoration. Full native 200% toolbar zoom still requires a manual check.
